\section{Detection and response}
\label{sec:detection}

The sensor reads the capture file the tap writes. It does not read the DNS log, the receiver log, or the scenario state. Seven rules are defined and five are reachable in a single-host run; the sensor's self-test produces the other two conditions, a hand-made lookalike domain and a second source address. Six of the seven rules key on lab-specific constants: four on the check-in suffix, one on the suffix plus a periodicity threshold, and one on the POST path, agent string and a non-global destination. Only \texttt{T5-C2-001} is generic, and it fires on the first contact with any new destination, including the benign update download. One rule reuses the lab's own \texttt{dga.decode\_label}, the same algorithm and fixed key as the implant, so a valid checksum shows that the lab's encoder ran, not that an unknown implant is present.

The claim the lab supports is narrower than ``the rules detect SUNBURST''. The check-in is decodable and periodic once captured, and the telemetry upload is visible on the wire. Mandiant rates a CNAME resolution above a decoded DGA label, because a decoded label shows only that the implant ran, while a CNAME can indicate follow-on command and control; the CNAME also requires a preceding A record in specific ranges~\cite{mandiant-sunburst-details}. The sensor parses CNAME records for DNS provenance, but no rule alerts on one. Four rules key on the label, \texttt{T5-BCN-001} on the suffix, and \texttt{T5-C2-002} on the upload path, agent and destination. The rule set shows what the lab's own key makes recoverable, not what a defender should prioritise.

The two response actions change lab state, not just the display. A resolver block makes the coordinator answer NXDOMAIN, and the implant sends one final mode-3 check-in and exits. Tap isolation installs an egress filter on the switch-side bridge port, so the victim's frames stop reaching the network while the capture keeps recording them. The resolver block is reversible in configuration but not in effect: the implant exits, and only a reinstall brings it back. Tap isolation is reversible. The console rejects a mode change while a block is active.
